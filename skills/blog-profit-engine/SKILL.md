# 블로그 수익화 엔진

검색 유입과 독자 신뢰를 기반으로 실행 가능한 수익형 블로그 전략을 만든다. 사용자가 원하는 한 가지 작업만 처리하거나, 요청이 넓으면 진단 → 우선순위 → 실행물 순서의 통합 플랜을 제공한다.

## 먼저 판단할 것

요청을 아래 모드 중 하나 이상으로 분류한다.

1. **주제 발굴**: 관심사·경험에서 경쟁 대비 기회가 있는 틈새 주제를 찾는다.
2. **초안 생성**: 주제와 키워드로 검색 의도에 맞는 글 초안을 만든다.
3. **수익화 개선**: 광고, 제휴, 협찬, 디지털 상품 등 수익 구조를 진단한다.
4. **SEO 점검**: 제목·본문·경쟁 문서·내부링크·발행 전략을 점검한다.
5. **콘텐츠 재활용**: 블로그 글을 숏폼, 카드뉴스, 뉴스레터 등으로 전환한다.
6. **성장 로드맵**: 목표 수익에 필요한 트래픽과 6~12개월 실행 계획을 설계한다.
7. **제작·임시 저장**: 키워드 기준에 맞춘 원고와 이미지를 완성해 블로그 편집기에 임시 저장하고 실제 저장 결과를 검증한다.

통합 요청이면 모든 모드를 기계적으로 나열하지 말고 현재 병목을 찾아 가장 영향이 큰 작업부터 제안한다.

## 입력 수집

이미 제공된 정보는 다시 묻지 않는다. 결과가 크게 달라지는 누락 정보만 한 번에 짧게 질문한다.

- 공통: 운영 플랫폼(네이버·티스토리·워드프레스 등), 현재 주제, 목표 독자, 운영 경험
- 주제 발굴: 관심사, 직접 경험·전문성, 주당 투자 시간, 꺼리는 분야
- 초안·SEO: 핵심 키워드, 검색 의도, 기존 제목·본문, 원하는 길이와 말투
- 수익화: 최근 30일 방문자 또는 페이지뷰, 현재 수익과 채널, 주요 유입 글
- 재활용: 원문, 배포 채널, 영상 길이 또는 카드 수, 브랜드 말투
- 로드맵: 월 수익 목표, 현재 트래픽·글 수·발행 빈도, 가용 시간과 예산
- 제작·임시 저장: 대상 블로그와 편집기, 시험/운영 모드, 문체 가이드, 이미지 스타일, 해시태그 기준

사용자가 바로 결과를 원하고 핵심 입력이 부족하면 합리적인 가정을 명시한 `빠른 초안`을 먼저 제공하고, 정확도를 높이는 데 필요한 정보만 끝에 요청한다.

## 공통 작업 원칙

- 검색량, 경쟁도, 상위 노출 글, 광고·제휴 정책처럼 변하는 사실은 가능한 경우 최신 자료를 조사하고 출처와 확인일을 남긴다. 조사 도구가 없으면 수치를 만들지 말고 `확인 필요`로 표시한다.
- 키워드 도구의 검색량과 블로그 플랫폼의 방문자 수를 같은 지표처럼 취급하지 않는다.
- 추정치는 공식처럼 단정하지 않고 보수·기준·낙관 시나리오 또는 범위로 제시한다.
- 검색 의도를 정보형·비교형·구매형·탐색형으로 구분하고, 글의 목적과 CTA를 일치시킨다.
- 독자에게 도움이 되는 정보가 먼저다. 일반 SEO 조언에서는 기계적인 키워드 반복을 권하지 않는다. 다만 제작·임시 저장 모드에서는 사용자가 지정한 규칙에 따라 선정 키워드별 본문 3~4회 사용을 계수하고 검증한다.
- 사용자의 실제 경험이나 사례를 지어내지 않는다. 필요한 부분은 `[직접 경험 추가]`, `[사진 추가]`, `[근거 확인]`처럼 표시한다.
- 제휴·협찬 콘텐츠에는 이해관계 공개 문구를 권하고, 플랫폼 정책과 관련 법규 확인을 안내한다.
- “수익 2배”는 보장하지 않는다. 현재 수익 구조를 기준으로 필요한 개선 폭을 역산하고 검증 가능한 실험으로 바꾼다.

## 결과 구성

항상 가장 중요한 결론을 먼저 쓴다. 긴 분석은 다음 순서를 기본으로 하되 요청 규모에 맞게 줄인다.

1. 핵심 진단 또는 추천
2. 근거와 가정
3. 바로 사용할 실행물(초안, 제목, CTA, 일정 등)
4. 우선순위가 있는 다음 행동
5. 측정 지표와 재점검 시점

표는 주제 비교, 수익 시나리오, 채널별 재활용처럼 반복 필드가 있을 때만 사용한다.

## 모드별 지침

- 주제 발굴, SEO 점검, 성장 로드맵은 [리서치·SEO·성장](references/research-seo-growth.md)을 읽고 따른다.
- 초안 생성과 콘텐츠 재활용은 [글쓰기·재활용](references/writing-recycling.md)을 읽고 따른다.
- 수익 모델 선택, 배치, CTA, 목표 역산은 [수익화 최적화](references/monetization.md)을 읽고 따른다.
- 원고·이미지 제작부터 블로그 임시 저장과 재검증까지 요청받으면 [제작·임시 저장 워크플로](references/publishing-workflow.md)를 읽고 순서대로 따른다.
- 여러 모드가 섞였으면 필요한 참고 파일만 읽는다.

## 완료 기준

결과는 일반론에서 끝나면 안 된다. 사용자가 다음 행동을 바로 시작할 수 있도록 최소 하나 이상의 구체적 산출물과 측정 기준을 포함한다. 현재 데이터가 부족한 경우에는 무엇을 어떻게 측정하면 다음 판단이 가능한지 명확히 적는다.
