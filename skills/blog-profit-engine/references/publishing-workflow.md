# 제작·임시 저장 워크플로

블로그 원고, 이미지, 해시태그를 완성해 편집기에 임시 저장하고 다시 열어 검증하는 작업에만 적용한다. 공개 발행은 이 워크플로의 범위가 아니다.

## 실행 전 경계

- 사용자가 편집기 입력 또는 임시 저장까지 명시적으로 요청한 경우에만 블로그 플랫폼을 변경한다. 원고 작성 요청만으로 외부 편집기 조작 권한을 추정하지 않는다.
- 모드가 지정되지 않았으면 비용과 시간을 줄이기 위해 시험 모드로 진행한다고 밝힌다. 사용자가 운영 모드를 지정하면 운영 모드를 따른다.
- 시험 모드는 이미지 3장, 운영 모드는 이미지 15장을 기획하고 실제 생성한다.
- 이미지 생성 기능을 사용할 수 없으면 생성했다고 말하지 않는다. 배치 가능한 이미지 프롬프트와 기획표를 제공하고, 이미지 생성과 편집기 저장이 완료되지 않았음을 명시한다.
- 공개, 발행, 예약 발행 버튼은 누르지 않는다. 임시 저장 기능이 없고 저장이 곧 공개를 뜻하는 플랫폼에서는 입력을 중단하고 사용자에게 알린다.

## 1. 독자와 검색 의도 정리

목표 독자를 한 문장으로 구체화하고, 독자가 검색하는 상황·해결하려는 문제·읽은 뒤 기대 행동을 적는다. 검색 의도는 정보형·비교형·구매형·탐색형 중 주 의도 하나와 필요한 보조 의도로 정리한다.

## 2. 키워드 선정

검색 의도와 직접 관련된 키워드 3~4개를 선정한다. 그중 글 전체를 대표하면서 제목에 자연스럽게 들어갈 한 개를 `대장 키워드`로 지정한다. 최신 검색 자료를 확인할 수 있으면 수요와 경쟁 근거를 남기고, 확인할 수 없으면 검색량을 추정해 만들지 않는다.

## 3. 키워드 배치 규칙

- 대장 키워드를 제목 후보 3개 모두에 포함한다.
- 선정한 키워드 각각을 본문 전체에서 3~4회 사용한다. 대장 키워드도 같은 기준을 적용한다.
- 소제목의 키워드는 본문 횟수에 포함하되, 제목과 해시태그는 포함하지 않는다.
- 띄어쓰기와 어절이 달라 의미가 흐려진 표현은 같은 키워드로 억지 계산하지 않는다. 최종 원고에서 실제 문구 기준으로 센다.
- 횟수를 맞추기 위한 부자연스러운 문장은 다시 쓴다. 정확성이나 문장 자연스러움과 충돌하면 억지로 넣지 말고 충돌을 보고한다.

## 4. 제목 후보와 원고 작성

대장 키워드가 포함된 제목 후보 3개를 만든 뒤 검색 의도, 구체성, 과장 여부를 비교해 최종 제목 하나를 고른다. 원고는 서론–본론–결론 흐름과 H2/H3 소제목을 사용하되, 독자 질문에 가장 빠르게 답하는 구조를 우선한다.

## 5. 자연스러운 한국어 편집

사용자가 제공한 문체 가이드를 우선 적용한다. 별도 가이드가 없으면 다음을 기본값으로 삼는다.

- 독자에게 설명하듯 명확하고 편안한 존댓말
- 짧은 문장과 긴 문장을 섞은 자연스러운 호흡
- 번역투, 불필요한 명사화, 같은 종결어미의 연속, 과장된 감탄을 줄임
- 추상적인 홍보 문구보다 조건, 방법, 한계, 판단 기준을 구체적으로 설명

편집이 끝난 뒤 키워드 횟수를 다시 세어 3~4회인지 확인한다.

## 6. 사실성과 경험 경계

제공되지 않은 경험, 후기, 사례, 수치, 성과를 만들지 않는다. 작성에 필요하지만 없는 내용은 `[직접 경험 추가]`, `[실제 수치 확인]`, `[출처 확인]`으로 표시한다. 생성 이미지도 실제 현장 사진이나 실제 사용 후기처럼 오인시키지 않는다.

## 7. 해시태그와 검색 유입 사전 점검

원고와 검색 의도에 직접 관련된 해시태그를 확정한다. 대장 키워드, 세부 주제, 독자 상황을 적절히 섞되 관련 없는 인기 태그를 넣지 않는다. 개수와 표기법은 대상 플랫폼의 최신 관행을 확인한다.

저장 전 다음을 점검한다.

- 최종 제목에 대장 키워드가 정확히 들어 있는가
- 키워드 3~4개가 본문에서 각각 3~4회 사용되었는가
- 제목, 도입부, 소제목, 결론이 같은 검색 의도에 답하는가
- 제목이 과장되거나 본문이 약속한 답을 누락하지 않았는가
- 제공되지 않은 경험·후기·수치·성과가 섞이지 않았는가
- 해시태그가 본문 주제와 직접 관련되는가

## 8. 이미지 기획과 생성

시험 모드는 3장, 운영 모드는 15장을 기획하고 생성한다. 먼저 `번호 / 역할 / 들어갈 위치 / 장면 또는 도식 / 생성 프롬프트 / 캡션·대체 텍스트`로 이미지 기획표를 만든다.

- 이미지는 표지, 핵심 개념, 단계 설명, 비교, 체크리스트처럼 서로 다른 역할을 맡긴다.
- 같은 구도의 장식 이미지를 반복하지 않는다.
- 글의 사실 관계를 왜곡하거나 존재하지 않는 제품 사용 장면, 후기, 전후 결과를 실제처럼 만들지 않는다.
- 생성한 이미지 파일 수와 기획 수가 일치하는지 확인하고 각 이미지를 직접 검토한다.

## 9. 편집기 배치와 임시 저장

최종 제목, 본문, 이미지, 해시태그를 대상 블로그 편집기에 입력한다. 이미지는 기획표의 위치와 순서에 배치하고 필요한 캡션 또는 대체 텍스트를 넣는다. 입력이 끝나면 공개 상태를 만들지 않는 `임시 저장`만 실행한다.

## 10. 저장 결과 재검증

임시 저장 완료 표시만 믿지 말고 저장된 글 목록이나 편집 화면에서 해당 글을 다시 연다. 다시 열린 저장본을 기준으로 다음을 검증한다.

- 제목이 최종 선택본과 같은가
- 본문 시작·중간·끝이 누락되거나 잘리지 않았는가
- 시험 모드 3장 또는 운영 모드 15장의 이미지가 올바른 순서로 남아 있는가
- 해시태그가 모두 저장되었는가
- 줄바꿈, 소제목, 링크, 캡션이 깨지지 않았는가
- 글 상태가 임시 저장이며 공개·예약 발행 상태가 아닌가

불일치가 있으면 공개 버튼을 건드리지 않고 수정 후 다시 임시 저장하고 한 번 더 연다. 같은 문제가 반복되면 현재 저장 상태와 남은 문제를 보고하고 중단한다.

## 11. 완료 보고

공개 발행하지 않는다. 완료 보고에는 최종 제목, 선정 키워드와 본문 등장 횟수, 이미지 모드와 실제 저장 장수, 해시태그, 임시 저장 여부, 재검증 결과, 남은 수동 확인 항목을 포함한다.
